# Mutation testing uses a repository-owned tool

CI gates on new surviving mutants in the Core and the Shell. The tester is `internal/tools/mutate`, a standard-library Go `main` package committed to this repository and run by `./scripts/mutation.sh`; versioning it with the reviewed tree pins it more strictly than a module version. It applies one edit at a time to a non-test file, including statement deletion and call deletion, and runs the mutants through a Go build overlay, so no tracked file is ever written. Each mutant is judged by the mutated package's own tests only: the Core's tests decide Core mutants and the Shell's tests decide Shell mutants. That keeps a verdict attributable to the package that owns the code and keeps the root end-to-end terminal suite out of a per-mutant loop. A mutant is *never executed* when the package's own tests' coverage profile records its statement block with a zero count and the mutant still compiles: such a mutant is built but never run, and a build that fails makes it *not viable* instead; a position the profile records no block for, such as a switch case expression or a package-level initializer, is run like any other mutant. Every other mutant gets a test run with a `-timeout` and a context deadline of `max(30s, 20 x baseline duration)`, measured from one coverage run of the package; a timeout counts as killed, because a hanging mutant is a detected mutant, and the generous multiplier keeps a slow-but-finishing mutant from flipping. Survivors and never-executed mutants fail the gate unless a justified entry in `mutation/exceptions.txt` names them, each identified by file, enclosing function, operator, before and after snippets, and an ordinal rather than a line number.

## Considered Options

- **gremlins v0.6.0.** A current Go mutation tool, but its default operators neither delete statements nor delete calls, so the `min(max(elapsed, 0), ElapsedLimit)` clamp deletion was never generated and the regression went unreported; with its default timeout coefficient every mutant timed out. Rejected.
- **go-mutesting.** Rewrites tracked files in place, which is unsafe while several agents share one working tree, and its blacklist identifies an entry with a whole-file checksum, so any unrelated edit orphans the entry. Rejected.
- **A third-party tool pinned in `tools/go.mod`.** Replaying a module pin still lets the tool drift from the reviewed tree and cannot provide this repository's exception reasons, identity scheme, or overlay-only execution. Rejected in favour of owning a small tool.

## Consequences

Mutation testing runs as its own CI job on Linux rather than inside the main gate, because it is slower and its failures name a plausible missing test rather than a broken build. The contract is zero surviving or never-executed mutants apart from justified exceptions: there is no untriaged category in which an unjudged mutant can hide, and an entry without a reason is a parse error. Killing a mutant makes its entry stale, and editing a mutant changes its identity, so `./scripts/mutation.sh -update` rewrites the list only to remove entries whose mutant is now killed, not viable or no longer generated; it never records a new survivor, and the gate fails on any unlisted survivor or stale entry.
